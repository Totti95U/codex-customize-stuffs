# Document an existing asset (write)

Read [the shared Notion workflow](../../references/notion-workflow.md) and the current Hub. Documentation changes require an explicit user request.

1. Find the exact existing Plugin or Content record and fetch its page plus the relevant data source schema. If identity or edition is ambiguous, resolve that before writing; do not create a new record through this skill.
2. Research official manual, official documentation, product page, then developer support. Use reliable secondary sources only when needed; mark community-only claims with lower confidence and avoid certainty. Retain links and the distinction between product facts, local availability evidence, and user experience.
3. Use the current Hub page format. Answer “When should I reach for this?” through Strengths, Weaknesses / Caveats, When I would choose this, Alternatives, and Starting points. Prefer comparisons with assets actually registered in the KB. Avoid exhaustive parameter lists and unverified ownership claims.
4. Preserve existing Personal notes and unrelated fields. Do not translate offline DSP ratio into realtime CPU class or reported latency 0 into verified zero latency. Update verification fields only when the evidence and request justify it.
5. Re-fetch the page and verify requested sections, sources, and untouched evidence. Return the page link, decision summary, source quality, and explicit unknowns.
